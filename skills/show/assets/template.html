1. The problem

A person deletes a note with one tap. The app removes the note from the device and from the server immediately. A person who taps the wrong note cannot get it back. Three persons reported this in October.

2. The solution: a deleted note goes into the trash

The app marks a deleted note with the time of the deletion. It does not remove the note. The note list hides each note that has this mark, and the trash shows it. The app removes a note fully when the note is in the trash for longer than a time limit.

How long does a note stay in the trash?

A longer time gives a person more days to find a mistake. It also uses more space on the server. One note uses 2 KB on average.

Where does a person open the trash?

The app has no menu today. Each drawing shows the note list of a phone after the change.

A protection against a lost restore (you do not decide this)

Two devices can change the same note at the same time. For example, one device restores a note while a second device without a connection deletes it fully. The server keeps the note in this situation, because a restore is the safer result.

One reviewer found this sequence in the code. Nobody saw it on a real device.

4. The code changes

Server

  • notes.sql gets the new column deleted_at.
  • NotesApi.delete sets the mark and does not remove the row.
  • A daily job removes each note that is past the time limit.

App

  • store.js hides the marked notes from the note list and from the search.
  • trash.js is new. It shows the trash and its actions.

Tests

  • 4 new tests for the server and 3 new tests in a browser.
  • I run each test on the old code first, and it must fail there.
Sketch of the server code 
// NotesApi.delete: the row stays, so a restore needs no backup
async function deleteNote(id, userId) {
  await db.run('UPDATE notes SET deleted_at = ? WHERE id = ? AND user_id = ?', [Date.now(), id, userId]);
  sync.notify(userId, { note: id, deleted: true });
}
